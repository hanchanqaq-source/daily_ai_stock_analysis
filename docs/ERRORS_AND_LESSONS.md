# 错误与经验

本文件记录 PP02 开发过程中可复用的错误、根因、修复和验证方法。

## 2026-07-29｜Electron productName 变更必须同步 macOS 验收路径

- 现象：electron-builder 已成功生成新名称的 `.app` 和 DMG，但
  `scripts/build-desktop-macos.sh` 返回“expected one unpacked macOS app, found 0”。
- 根因：`package.json` 的 `productName` 已改为
  `PP02 AI Daily Stock Analysis`，验收脚本仍用旧固定路径
  `Daily Stock Analysis.app` 查找未打包应用及 DMG 内应用。
- 修复：同步两个 App 路径，并在 Desktop 单测中同时断言 PP02 名称存在、旧固定
  路径不存在。
- 验证：必须同时运行 Desktop Node 单测和 macOS unsigned Desktop package 门；
  单看 electron-builder 成功不足以证明验收脚本兼容新产品名。


## 2026-07-29｜产品级安全默认必须同步集成断言与设置帮助

- 现象：自动通知总开关实现后，完整后端门只剩 2 项失败：旧集成测试仍断言默认
  `notify=true`，新设置字段缺少 Web 帮助元数据。
- 根因：实现已改变产品级默认，但一个跨层测试和一个用户可见配置消费者未同步。
- 修复：将无显式开启的 API 集成断言改为 `notify=false`；为设置 Registry 补
  `help_key`，并补齐中英文标题、说明和帮助。
- 验证：安全默认改动必须同时覆盖真实入口行为、旧集成断言、配置 Registry、
  Web lint/build 和完整离线测试；仅让新增单元测试通过不足以收口。


## 2026-07-30｜新增前端测试门前必须先区分范围内失败和既有测试债

- 现象：R3.3 首次把 `npm test` 加入 `web-gate` 后出现 2 项失败：快捷持仓页面
  测试按预期失败；另一个 AlertRuleForm 测试要求日股/韩股选项，但现有告警组件
  只有中/港/美选项。
- 根因：原 `web-gate` 只执行 Lint 和 Build，97 个 Vitest 文件没有作为 PR
  阻断门；新增全量测试第一次暴露了与 R3.3 无关的历史契约不一致。
- 处理：R3.3 将正式新增门收敛为 PortfolioPage 专项测试，保证当前功能测试可阻断；
  告警日/韩市场不在本切片中修改，避免用无关补丁扩大产品范围。
- 验证：RED 时 PortfolioPage 为 1 fail / 28 pass；GREEN 为 29/29 pass；
  完整后端和 8 个 CI Job 同时通过。
- 经验：给既有大仓库启用此前从未运行的全量测试时，应先建立基线、标记历史失败，
  再决定独立治理切片；不能把历史失败误判为当前功能回归，也不能静默忽略。

## 2026-07-30｜目标持仓确认不得重复记录交易现金变化

- 现象：R3.3 计划写“交易/现金事件”，容易被误读为一次确认同时写交易和资金流水。
- 根因：官方组合重放已根据买卖交易自动增减现金；再写同额资金流水会造成双重扣款
  或双重入账。
- 处理：快捷持仓确认只追加一条官方交易事件，预览中的现金变化仅作展示；入金、
  出金仍使用独立资金流水。
- 验证：测试确认预览阶段交易数不变，确认后只增加一条交易，重放持仓达到目标数量。

## 2026-07-30｜异步 UI 测试必须等待状态提交而非只等待元素出现

- 现象：同一 R3.3 代码在实现 Run 中 Web 29/29 通过，Judge Head 重跑时既有
  “切换账户后丢弃迟到汇率结果”用例偶发读到“刷新中...”按钮尚未禁用。
- 根因：`findByRole` 只保证匹配文字的按钮已经出现，不保证 React 的
  `disabled` 状态已经在同一时刻提交；断言存在调度竞争。
- 修复：改用 `waitFor` 明确等待按钮进入禁用状态，业务实现和 R3.3 契约不变。
- 验证：修复 Head 必须重新运行 PortfolioPage 29 项测试及完整 8 门 CI；不得把
  单纯重跑成功当作修复证据。
- 后续：R3.4 又在同文件“切换成本法”用例发现一处相同旧写法；同类根因确认后
  必须检查相邻测试，而不能只修最先失败的一行。最终 PortfolioPage 31/31 通过。

## 2026-07-30｜校验后的备份对象仍需在摘要边界做类型规范化

- 现象：股票备份导出测试通过，但恢复预览 4 项失败，错误为
  `Object of type datetime is not JSON serializable`。
- 根因：导出对象使用 ISO 字符串；严格校验为了写入 ORM，把日期字段解析回
  `date/datetime`。摘要函数仍假设输入完全是 JSON 标量。
- 修复：摘要 JSON 的 `default` 只接受 `date/datetime` 并转换为稳定 ISO 文本；
  未知对象继续抛 `TypeError`，不使用会隐藏契约错误的通用 `default=str`。
- 验证：Run `30519559480` 后端 `4987 passed`，覆盖预览只读、过期令牌、
  原子替换、失败不改原库和恢复后官方重放。

## 2026-07-30｜GitHub Actions 零 Step 失败先检查账户额度

- 现象：同一 Workflow 的两个首发 Job 在零 Step、零日志状态立即失败，其余门
  全部跳过；重跑失败 Job 仍完全复现。
- 根因：私有仓库已用完账户 2000 分钟免费 Actions 额度，不是代码或 Workflow
  配置失败。
- 处理：先审计 Git 历史、分支、PR、配置、数据文件和可读 Job 日志，确认没有
  密钥或真实数据；用户明确授权后把 PP02 改为 Public，标准 Runner 立即恢复。
- 经验：零 Step 失败不能靠空 Commit 反复撞 CI；先区分平台调度、账户额度和代码
  失败。公开仓库会公开代码、分支、PR 和 Actions 历史，必须先审计再变更。

## 2026-07-30｜新增历史快照必须隔离既有事实查询

- 现象：R3.5 复用 `AnalysisHistory` 保存 `period_outlook`，初版服务能正确聚合，
  但既有股票柱状历史和回测查询会把所有非 `market_review` 记录当作股票事实。
- 根因：旧查询建立时只有普通分析和市场复盘两类报告，使用“排除市场复盘”的
  开放式条件；新增正式报告类型后，该假设不再成立。
- 修复：普通股票历史和回测改为显式排除 `period_outlook`，并新增兼容测试证明
  `report_type=NULL` 的旧正式分析仍保留。
- 经验：在共用历史表中新增可识别报告类型时，要同时检查所有开放式
  `!= old_type` 查询；复用事实表不等于让新快照参与旧统计。

## 2026-07-30｜额外全量测试失败需与正式阻断门分层判断

- 现象：R3.5 正式 Web 阻断套件 `55/55`、Lint 和 Build 均通过；额外运行全量
  Web 基线时得到 `1044 passed, 2 skipped, 1 failed`。
- 根因：既有 `AlertRuleForm` 一条测试要求出现 JP/KR 选项，紧邻既有测试又明确
  要求 JP/KR 不出现；生产市场选项和 R3.5 均未修改。
- 处理：记录为既有契约矛盾，不修改无关产品或测试来制造全绿；R3.5 仍以
  Workflow 定义的四文件 55 项阻断套件与完整 8 门 CI 为验收依据。
- 经验：主动扩大的非门禁测试有红灯时必须披露并定位，但不能把互相矛盾的旧契约
  偷带进当前功能切片；应另立治理任务统一产品裁决。

## R3.6｜便携更新不能复用安装器信任假设

便携 ZIP 没有 NSIS 安装事务，不能在摘要、身份、路径和逐文件清单校验前停止旧版本或覆盖文件。首次升级没有旧清单时也不能猜测“旧程序文件”；只覆盖新清单列出的路径，并保留所有未知文件。

## R3.6 Review｜CI 全绿不能替代真实更新事务

便携更新助手必须脱离 `app.asar` 和待替换目录运行；运行时状态只能在旧后端确认退出后备份，并记录文件原先是否存在。新版本必须通过显式 plan/readySignal、动态端口、产品、版本、token 和主页加载握手；失败时先停止新 Electron 进程树及其后端，再完整恢复。任何恢复错误都必须保留备份并记录为失败，不能用“已回滚”掩盖部分恢复。


## R3.6 R5｜静态导入和 CI 全绿不能证明冻结服务可启动

PR #7 的 Windows 候选在 CI 8/8 后仍因 PyInstaller 未包含 `fake_useragent.data` / 浏览器数据而实机启动崩溃。依赖包含包内资源时，必须同时设置兼容版本范围、显式 `--collect-all`，并在冻结产物中实际执行数据加载和真实业务导入链。上传候选前还必须用隔离环境、动态端口启动最终冻结 EXE，验证 `/api/health` 与主页，并可靠清理整个进程树；否则静态 import probe 与构建成功均是假证据。
