  脱敏或迁移真实数据库。

## 目标

建立一个可重复、默认拒绝真实数据的迁移演练入口，证明兼容的股票事件账本可以从
合成 SQLite 输入迁入全新 PP02 空库，同时排除用户档案、基金、密钥、派生持仓、
缓存和日志，并用失败演练证明目标库保持不变。

## 方案比较与裁决

1. **采用：合成证明绑定 + 临时副本 + 现有备份恢复契约。** 输入必须带有与文件
   SHA-256 精确绑定的合成数据证明。原库只读检查，升级只发生在临时副本；迁移复用
   `DatabaseManager` 和 `PortfolioBackupService`，不建立第二套账本。
2. 不采用：直接用 SQL 把旧表复制到新库。该方案会复制无关表并重复 R3.4 校验。
3. 不采用：只写测试、不提供可重复脚本。该方案不能形成 R4 的操作和回滚证据。

## 组件与数据流

### `src/services/database_migration_rehearsal_service.py`

- 校验输入、证明文件、SQLite 头、完整性和 SHA-256。
- 证明只接受 `classification=synthetic` 且 `contains_real_data=false`。
- 空库可进入演练；只要出现部分股票事件表，就必须满足四张正式事件表及必需列。
- 原输入使用 SQLite 只读 URI 检查；任何升级只在自动清理的临时副本上执行。
- 从临时副本调用现有股票专用导出，再向全新目标库执行预览和确认恢复。
- 在独立探针库用过期预览令牌制造失败，证明原有哨兵账本不变。
- 报告只包含表名、计数、摘要和布尔证据，不包含账户名、备注、交易正文或备份正文。

### `scripts/pp02_database_migration_rehearsal.py`

提供显式 CLI：输入 SQLite、合成证明、工作目录和 JSON 报告路径。目标库和报告不得
与源文件重合；发生失败时返回非零，并使用不含原始行值的错误信息。

### `tests/test_database_migration_rehearsal.py`

全部 fixture 在临时目录动态生成，不提交 `.db`。覆盖：空库、混合旧表、正式股票
事件、排除敏感/基金/派生表、源文件不变、证明缺失/篡改/声明真实数据、部分 Schema、
目标摘要一致、回滚探针和 CLI 报告不泄漏假敏感值。

## 输出契约

成功报告固定包含：

- `report_version`、`status`、`source_sha256`、`source_unchanged`；
- Schema 兼容结果和被排除表名；
- 四类股票事件迁移计数及迁移前后规范化摘要是否一致；
- 回滚探针是否拒绝过期预览、哨兵是否保持不变；
- `real_data_used=false`、`backup_payload_persisted=false`。

报告不得包含输入行值、账户/券商名称、备注、密钥样式文本、完整 SQL 或备份 JSON。

## 失败与回滚

- 证明缺失、哈希不匹配、非合成数据、非 SQLite、完整性失败、部分事件 Schema、
  校验失败或目标摘要不一致：在写正式目标前失败。
- 目标恢复失败：删除未完成的新目标；源文件不变。
- 回滚探针失败或哨兵变化：整次演练失败，不输出 PASS。
- 临时源副本和失败探针无论成功或异常都清理。
