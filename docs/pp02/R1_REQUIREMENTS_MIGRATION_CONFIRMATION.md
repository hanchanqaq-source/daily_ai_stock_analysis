# PP02 R1 需求与旧功能迁移确认

结论：`R1_REQUIREMENTS_AND_MIGRATION_SCOPE_CONFIRMED`

本报告以官方 `v3.28.0`（`905c339d80ad2daa6fd2bab3bb10267b23c7ac1c`）
和 PP02 Draft PR #3 为基线，记录旧 PP02 功能的最终产品取舍。R1 只确定范围，
不表示对应功能已经实现。

## 固定产品边界

- PP02 只包含股票和 ETF；基金能力全部属于 PP03。
- PP02 保持官方单用户模式，只供一个人本机使用。
- 不迁移用户档案、用户切换、当前用户持久化、按用户隔离历史或用户级备份恢复。
- 不新增多用户、多租户或平行持仓模型。
- 官方账户、交易、现金、公司行动和持仓重放链是股票持仓唯一事实源。
- 手动分析是默认入口；本地定时、GitHub Actions 定时和自动推送默认关闭。
- 周期报告只在应用内手动查看，不建立周五自动 Workflow。
- Windows 实机验收标记为 `Deferred`；D 盘目录缺失不阻塞云端开发。

## 保留官方实现

1. 多市场股票与 ETF 分析、行情、新闻、基本面和市场复盘。
2. 手动单股/批量分析、任务进度和分析历史。
3. React Web、FastAPI、Electron Desktop。
4. 官方设置 Schema、模型/通知测试和运行时调度能力。
5. 官方股票组合账户、事件账本、持仓重放、风险计算和 CSV/Futu 只读导入。
6. SQLAlchemy 与单 SQLite 数据链。
7. Windows NSIS 安装版、免安装 ZIP 和现有桌面更新保护链。
8. 官方 v3.28.0 已包含的海外新闻修复和多市场兼容能力。

## 调整后迁移

| 能力 | PP02 处理方式 | 硬边界 |
| --- | --- | --- |
| 产品与 Release 身份 | 将桌面产品名、技术 ID、产物名、更新源和 Release 地址改为 PP02 | 不改变官方来源记录和 License |
| 默认安全策略 | 保留调度和通知能力，但所有自动入口默认关闭 | 手动通知测试仍须用户主动点击 |
| 快捷持仓体验 | 在官方事件账本上增加快捷录入、调整预览和历史回看 | 不写入第二套持仓表 |
| 股票备份恢复 | 建立股票专用、版本化、先预览后确认的备份契约 | 不包含基金、用户档案、密钥和派生快照 |
| 周期报告 | 手动查看本周至今、邻近周、5周、10周、1个月和2个月 | 不建立自动周报或自动推送 |
| Windows 便携更新 | 作为后续独立切片，复用校验、备份和回退设计 | 不阻塞 NSIS 主发布形态 |
| Windows 安全凭据 | 等设置架构稳定后独立实现 DPAPI/safeStorage | 不把旧版部分实现视为已完成 |

## 不迁移

1. 所有基金中心、基金自选、基金持仓、基金穿透和基金建议。
2. 股票/基金双中心、双域 React Context 和基金数据库表。
3. 本地用户档案、多用户切换、用户级隔离和用户级备份恢复。
4. 旧版平行快捷持仓表、平行行情 Provider 和静态市场看板。
5. mock-only、fixture-only、dry-run-only 和演示页面。
6. 旧周五自动周报 Workflow、自动 Discord 推送和机器人监听。
7. `repository_dispatch` 外部命令层和将 `data/history` 回推 Git 的流程。
8. 旧版海外新闻补丁、旧依赖锁、旧治理文件和证据包整包搬迁。
9. `.env`、Token、API Key、Webhook、真实数据库、日志、缓存和构建产物。

## 冲突处理

| 冲突 | 裁决 |
| --- | --- |
| 官方事件账本与旧快捷持仓表 | 只保留官方事件账本；快捷体验必须转换为正式事件 |
| 官方单用户与旧用户档案 | 保持单用户；旧用户功能全部不迁移 |
| 旧备份的 replace-all 与基金混入 | 重建股票专用备份，默认预览，确认后单事务写入 |
| 本地调度关闭但 Actions 仍有 cron | 自动入口必须逐层关闭，不能只依赖 `.env` |
| 已配置通知密钥可能随分析自动发送 | 增加独立的自动通知总开关，默认关闭 |
| 桌面更新仍绑定官方仓库 | 在任何 PP02 Release 前先完成更新源和产物身份切换 |
| 旧 DPAPI 链不完整 | 延后重实现，禁止形成两套密钥真源 |

## 默认执行取舍

- Windows 第一阶段以 NSIS 安装版为主，并保留免安装 ZIP；便携版自动更新后置。
- 核心迁移阶段沿用 v3.28.0 现有配置机制；完整 DPAPI/safeStorage 后置。
- 上述排序只控制开发先后，不授权 Ready、合并、Release 或真实数据迁移。
